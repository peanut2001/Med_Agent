## 通过的链路

- `/health`、首页、注册、登录：HTTP 200；未登录 `/chat`：401。
- 真实对话成功返回：`Noted for this conversation: BLUEWHALE-739`，约 98 秒。
- 真实样例胸片上传路由到 `CHEST_XRAY_AGENT`，执行本地分类并创建复核任务：200，约 108 秒。
- 重新读取历史时恢复待复核 ID；复核拒绝和重复提交均返回 200，仅保存一条复核消息。
- 其他用户访问该历史、提交该复核：403。
- 删除对话后，旧复核请求及历史访问：404。
- 大图片：413；错误扩展名：400；已登录源文档访问：200。
- 取消预创建的 trace：200；使用已取消 trace 提交聊天：409。
- 模型处理期间健康检查仍可响应，观察到约 16 毫秒。
- 服务重启后医疗上下文恢复：临时模型回调确认模型收到年龄 42 岁和咳嗽两天的历史，复测最终回答正确，约 47 秒。
- 临时 PostgreSQL：原生 `postgresql://` 可以初始化 checkpoint；SQLAlchemy 的 `postgresql+psycopg://` 可以执行 `SELECT 1`。

## 实际发现的问题

1. **输入护栏误拒绝医学引用请求。**
   输入 `What are the common types of brain tumors? Use the medical knowledge base and cite the source documents.`，
   返回 `INPUT_GUARDRAILS`，拒绝理由为 `Requests source documents/citations`。
   当前护栏提示词明确禁止询问来源、参考文献、DOI 等，和 RAG 引用功能冲突。

2. **当前环境代理影响内网嵌入请求。**
   普通脑肿瘤问答进入 RAG 后返回 500，失败位于 Qdrant 初始化校验调用嵌入模型时。
   对同一内网嵌入接口，HTTPX `trust_env=True` 返回 502，`trust_env=False` 返回 200。
   项目 `OpenAIEmbeddings` 绕过环境代理后成功返回 4096 维向量。
   在独立测试进程将内网服务主机加入 `NO_PROXY` 后，实际混合检索返回 5 个文档。
   此覆盖仅用于测试进程，未更改项目 `.env`。

3. **远程重排接口不可用。**
   内网 `/v1/rerank` 返回 503，系统正确回退到原始检索排序。
   在绕过代理的独立进程中，实际检索与答案生成完成，但未使用重排。

4. **PostgreSQL 连接格式不兼容已确认。**
   checkpoint 直接传入 `postgresql+psycopg://` 会报 `ProgrammingError`；
   换成 `postgresql://` 成功。当前同一配置同时供 SQLAlchemy 和 Psycopg 使用，需分别规范化。

5. **护栏对普通多轮对话的策略不一致。**
   第一轮允许记住测试项目名，第二轮追问却返回仅支持医疗问题。
   医疗场景测试记录了患者年龄 42 岁、咳嗽两天；重启后历史仍返回 200，
   第一次最终回答却声称缺少早前信息；增加临时模型回调后重启复测，
   模型收到完整历史，原始回复和审核后的回复均正确。
   恢复逻辑有实际通过证据，但首次回答失败的模型/审核原因未能确定，回答稳定性仍需关注。

6. **既有 RAG 来源链接仍包含旧地址。**
   实际生成的引用包含 `http://localhost:8000/./data/raw/...`。
   链接来自已有知识库元数据，在其他端口或部署域名下可能失效。
